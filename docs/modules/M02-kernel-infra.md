# M02 — Инфраструктура ядра

**Статус:** `not_started`  
**Зависимости:** M01

## Цель

Сделать ядро отлаживаемым: логи, panic, маленькая lib, порядок в коде.

## Теория

- Early console и уровни логов
- `noreturn` panic / halt loop (`cli` + `hlt`)
- Набор `string`/`memory` функций без libc
- Ограниченный `snprintf`/`kvprintf`
- Инварианты, `assert`, когда assert оставлять в ядре
- Структура каталогов и naming conventions ConGroo

## Углубление

- Почему логирование из прерываний опасно (подготовка к M03)
- Целочисленный printf: `%s %c %d %u %x %p`
- Alignment и `packed` для будущих таблиц (IDT/GDT)

## Практика

- `printk` / макросы уровней
- `panic`
- `lib/string.c`, `lib/mem.c`
- Намеренный panic-сценарий (под флагом/командой сборки или временным вызовом)

## Acceptance criteria

- [ ] Единый формат логов
- [ ] Panic печатает сообщение и останавливается предсказуемо
- [ ] Базовые lib-функции покрыты простыми самопроверками (можно в `kmain` под `#ifdef`)
- [ ] Код разложен по файлам, не один «god file» на всё будущее

## Контрольные вопросы

1. Чем `panic` лучше бесконечного цикла без сообщения?
2. Почему `strlen` на невалидном указателе — это уже история про UB/fault?
3. Что значит freestanding для заголовков (`stdint.h` vs `stdio.h`)?

## Выход

PASS → M03.
