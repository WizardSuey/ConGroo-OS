# ConGroo Runtime — как философия живёт в системе

Этот файл — продуктовая спецификация поведения ОС.  
Источник законов: [`../PHILOSOPHY.md`](../PHILOSOPHY.md).  
Сюда смотрим, когда пишем ядро, шелл и USERGUIDE — не когда составляем учебный план.

---

## 1. Идентичность при boot

Минимальный баннер (смысл обязателен, формулировки можно уточнять):

```text
ConGroo
runline <boot_id>
retention: <cold|warm>
congruence: pending
```

- `boot_id` растёт между запусками, если есть хоть какая-то retention; иначе честно `cold`.
- Никаких внешних цитат и «пасхалок-франшиз».

---

## 2. Retention (Закон III)

Обязательный witness-набор v1 (в RAM + вывод в serial):

| Артефакт | Назначение |
|----------|------------|
| log ring (`dmesg`) | Единственный свидетель ранних событий |
| counters | ticks, syscalls, faults, ctx switches, panics |
| `last_stop` | `halt` / `panic` + короткое reason |
| Divergence Index | Функция от warn/fault/panic (формула простая, документированная) |

Правила:
- нет API «обнулить divergence, чтобы выглядеть здоровым»;
- reboot может стереть RAM — тогда witness обязан хотя бы **дожить до serial dump** в момент смерти;
- цель v2: persist journal (файл/virtio/NV), не амнезия.

Команды шелла (имена-ориентир):
- `dmesg`
- `div` — показать index + разбивку
- `witness` или `lastpanic` — последний стоп

## 3. Basins (Закон I)

Ведём явный список бассейнов в `docs/os/BASINS.md` (создаётся по мере открытия):

Пример записей:
- `basin.silent_hang` — нет логов, нет halt;
- `basin.panic_everything` — любой сбой = death ядра;
- `basin.amnesia` — сбой без witness.

Каждый закрытый basin = design win, не просто bugfix.

Runtime должен помогать узнавать basin:
- watchdog/uptime heartbeat (позже);
- panic вместо mute;
- рост Divergence Index при повторяющихся fault patterns.

## 4. Third Path (Закон II)

Политика по умолчанию:

| Событие | Плохая бинарность | Third path ConGroo |
|---------|-------------------|--------------------|
| bad pointer в user | «игнорировать» / «убить ядро» | убить/остановить **процесс**, ядро живёт, witness пишет |
| OOM в kernel alloc | «всегда panic» / «вернуть мусор» | отказ + лог; panic только если продолжать нельзя |
| неизвестный syscall | «молча noop» / «halt» | ошибка вызывающему + счётчик |
| повреждение ядра | «надеяться» / … | честный panic + dump |

Шелл и ABI обязаны показывать оператору *какой путь выбран*.

## 5. Mask & Charge (Закон IV)

| Слой | Тон |
|------|-----|
| Banner / редкие status line | допускается lab-драма |
| `printk` info/warn | сухо, точно |
| `panic` | максимальная правда, минимум позы |
| Документация ABI | без театра, только charge |

Инварианты (charge):
- silent UB в путях ядра — дефект философии, не «стиль»;
- каждый syscall имеет определённый errno-смысл;
- невозможность продолжать = panic, не undefined idle.

---

## 6. Reweigh (Закон V)

Стабильность runline измеряется так:
1. Есть история прошлых смертей/faults (хотя бы в notes + counters сессии).
2. Повтор старого сценария смерти больше не приводит в тот же basin — или это честно открытый долг.
3. Запрещено объявлять «congruence: ok», если witness потерян и мы просто «надеемся».

`congruence: ok` на halt означает: оператор **сознательно** завершил сессию, retention сброшен/удержан по правилам, система не притворяется.

---

## 7. Empathy layer (следствие главного тезиса)

ConGroo полезна, когда помогает человеку:

- понять, что случилось (witness);
- не потерять всю лабораторию из‑за одной user-ошибки (third path);
- увидеть, в какой basin его снова тянет (div);
- запустить свою программу и получить честный отказ, а не проклятие.

Приоритет фич:
1. ясность сбоя  
2. изоляция вины  
3. запуск программ оператора  
4. удобства и декоративный тон

## 9. Definition of Done для «философия вшита в ОС»

Философия считается реализованной не когда красиво в README, а когда:

- [ ] boot говорит runline/retention/congruence
- [ ] panic всегда оставляет witness в serial
- [ ] user-fault не обязан убивать ядро
- [ ] есть `dmesg` + `div`
- [ ] нет «косметического» wipe метрик
- [ ] USERGUIDE объясняет basins / third path / retention словами продукта
- [ ] в публичном UX нет внешних отсылок
